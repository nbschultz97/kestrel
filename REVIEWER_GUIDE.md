# KESTREL reviewer first-launch checklist

For the v0.44.1 Windows alpha: package `v0.44.1-alpha`, tag `v0.44.1-alpha.1`, source `1b6c007a878085f4ff59a74e7d47e8124fb6d688`. The final package passed 25 native tests and 218 launcher tests, with rendered layout and file-inspection checks. This checklist is guidance for your own review, not a claim that every manual interaction or physical controller was tested. The default updater serves v0.44.1 after a verified v0.44 upgrade and rendered restart.

1. **Download and extract.** Get `KESTREL-alpha-win64.zip` from the [official v0.44.1 release](https://github.com/nbschultz97/kestrel/releases/tag/v0.44.1-alpha.1). Compare its SHA-256 with the release checksum. Extract the complete archive into a new folder; keep all packaged folders together and do not mix versions.
2. **Open the launcher.** Run `KESTREL.exe` from the extracted folder, not from inside the ZIP or through the nested Unreal executable. Record `version.txt` and `source-commit.txt` for the installation you actually review. The launcher checks the stable update channel, so record the version after any update too.
3. **Check your input.** For a gamepad or RC radio, open **Settings > Controller**, detect and calibrate it, check axis directions and save. USB radios need joystick mode. For keyboard input, disconnect an unconfigured controller that takes over the axes and review the on-screen controls. Compatibility with every physical radio is not established.
4. **Inspect a starter aircraft.** Open **Work Bench**, select a stock starter aircraft and inspect its preview and selected inventory. Existing builds can require another inventory; use the displayed inventory action if a required source is available. Record blank previews or compatibility warnings. Saving a build does not itself launch it.
5. **Check presentation.** In Settings, choose your display and window mode. Confirm **Keep changes** only if the result is usable; unconfirmed display changes revert after 15 seconds. Windows x64 is supported; exact minimum hardware performance is not certified. Allow room for extraction, update staging and caches.
6. **Try read-only Flight Review.** Open an ArduPilot DataFlash `.BIN` recording. Use the visible playback and camera controls; do not assume a control marked unavailable will work. **Tab** expands/minimizes review controls, **T** toggles the trail, and **Escape** opens the normal pause menu. Check whether displayed telemetry and playback state are legible and whether a duplicate vehicle appears. This reviews an existing recording; it does not execute a real-aircraft mission.
7. **Optional file inspection.** In **Data & Catalogs > Flight files**, inspect a Mission Planner **QGC WPL 110** export. This is read-only file inspection, not playable mission import. Do not rename another log format to `.BIN` to make it appear supported.

**What to expect:** The public build includes its intended terrain configuration, but streamed scenery still needs Internet access, service availability and loading time. The offline Test Range is not a cached globe. Representative fixed-wing, rover and submersible visuals remain; detailed new models and exact-airframe identification are not included. Customer libraries stay local and are excluded from the download; merely referencing raw GIS or point-cloud files does not render customer 3D scenery.

**If Windows blocks launch:** This package is not publisher-signed. Retain the exact warning or error and request a supported installation path from the project or your administrator. Do not disable Windows or organizational protections. The ZIP is not a Windows runtime installer.

**Report a problem:** Press **F9** for a local bug report under `Documents\KESTREL\reports`. Record the version, source commit, steps, expected result and actual result. Include a screenshot where useful, `CeradonSim\Saved\Logs\CeradonSim.log`, and `KestrelLauncher.log`. Review files for sensitive information before sharing with `contact@ceradonsystems.com`. **Settings > Share reports** controls uploads; an offline local report is not proof of a successful upload.

This checklist covers ordinary installation and read-only review. Consult the release notes for the exact build and its verified scope.
